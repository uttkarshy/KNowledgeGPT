# Security and privacy review

**Release decision: hold.** The review covers source and an isolated test installation of the service. Production secrets, cloud account state, user files, SMTP delivery and the release certificate were outside the evidence available.

| Area | Evidence and residual work |
|---|---|
| Session credentials | Mobile keeps access tokens in process memory and persists only renewal credentials in Expo SecureStore. It scopes the storage key to the service origin, coalesces refreshes and clears local state before best-effort server logout. Main now serializes refresh rotation and commits replay revocations. Existing access tokens can live until expiry; verify recovery-line token-version invalidation. |
| Email / OAuth | Prior main printed email bodies when SMTP was absent. Feature branch suppresses that output. Main and recovery differ on recovery-token handling. Confirm expiring, single-use verification/reset links, real mail delivery, reset revocation, Google state/verified-identity handling and appropriate rate limits in staging. Android currently supports password accounts. |
| Tenant privacy | The isolated two-account test covers list visibility and authorization of document status, message history and answer reporting. Retrieval filters by the owning knowledge base and user. Audit every newer analytical path on the actual deployment. Server-side controls remain authoritative. |
| Uploads | Android restricts extensions, checks a file’s actual local size, uses a system picker and removes its cache copy after the attempt. The storage PUT carries only the signed URL and content type. Main now validates object length and confines worker scratch filenames. Recovery adds size/page limits and parser safeguards. Check production ClamAV availability, bucket policy, signed URL expiry, lifecycle and storage/provider deletion. A process kill can leave a cache file until Android clears it. |
| Chat and RAG | Sources are server-returned records with page/section and excerpts. Formatting disables external answer images/link navigation. Retrieved content can contain misleading instructions. Source scoping and system instructions reduce risk; validate behavior on an evaluation corpus and implement moderation for restricted content on the production provider. Flagging is only operational after an operator mailbox and review process are live. |
| Network | Production API origin and signed PUT require HTTPS. Client timeouts, 401 renewal, terminal SSE checks and explicit retry reduce duplicate actions. Stopping a stream can leave server work or charges in flight. Check refund and idempotency behavior on the actual credit service. Raw API status_detail may contain server-specific error text on older deployments. |
| Rate and cost controls | Main’s Redis auth limit fails open on Redis loss. Recovery implements per-account/global chat limits, processing limits and credit accounting. Select and stage a production-compatible backend with appropriate limits, alerting and verified provider quotas. |
| Deletion | User requests and reporting are server-delivered through SMTP and use a minimal receipt. The operator must verify mailbox control before erasure. Missing SMTP returns an error. The mailbox, retained copies, missed jobs and backups require an operational test. See operator.md. |
| Deployment | Main’s development JWT defaults must never be used on the service. Verify the operator uses a private signing secret, least-privilege IAM, private storage, database access controls, encrypted transport and redacted error handling. Public live response codes alone do not establish production security. |

## Dependency findings, 23 November 2026

- The Python requirements initially resolved advisories in python-jose and ecdsa. The feature branch migrated to PyJWT, keeping the existing JWT format. A fresh requirements-based pip-audit found zero known vulnerabilities. A requirements range can resolve differently later.
- The installed mobile lockfile’s production npm audit reported **5 high, 10 moderate, 0 critical**, including transitive packages. The previous Markdown parser advisory was removed with a patched parser. Investigate decode-uri-component through Expo Router and Zod through the Expo CLI separately. The CLI belongs primarily to build tooling, while deep-link parsing can reach the installed app. Upgrade the supported Expo dependency set and rerun device regression before release.
- The original main website lockfile reported **1 critical and 5 high**. The Android feature branch updates Next 15, the form resolver, Zod and PostCSS. On its revised lockfile the production npm audit reported **0 findings**, and the optimized Next.js production build passed. The deployed lockfile is unknown.
- Native binary and SDK supply-chain review, Play SDK Index warnings and a release-signed binary check remain prerequisites to final security acceptance. No production penetration testing was performed.

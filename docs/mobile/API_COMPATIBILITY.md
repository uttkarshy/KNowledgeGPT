## Mobile integration

The HTTPS origin is the existing website. Its public gateway returns 401 for protected profile, document, base, session, upload-limit and credit reads. Root OpenAPI and health return 404 there. These checks establish gateway behavior. They do not identify the deployed commit or establish authenticated parity.

Login returns bearer and rotating refresh tokens. The client holds access tokens in memory, persists the refresh token in SecureStore, coalesces renewals and replays a rejected authenticated request once. A network failure preserves the renewal credential. Logout clears the device session and attempts server-side revocation. An offline logout leaves remote revocation unconfirmed.

Upload is a binary PUT to the exact HTTPS URL returned by the API, without an API bearer token. Newer servers expose limits, an estimate and optional retry. The client obtains an estimate before confirmation. Only an explicit 404 on the limits lookup selects the older contract. Polling uses the authenticated document list to collect status and progress. No download-original endpoint exists.

Chat is POST plus text/event-stream. Events include delta, no_answer, done and error. The client incrementally decodes UTF-8, checks the terminal frame and renders persisted citation details. The recovery branch accepts Idempotency-Key for credit charging. Its charge key does not guarantee exactly-once message generation. Stop cancels the local request. Neither source defines a remote cancel or refund guarantee.

Restore and review account support after production reconciliation. The three /api/support routes and the public /privacy, /terms and /delete-account pages were added only on this Android branch.

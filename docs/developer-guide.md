# Developer Guide

## Running tests

```bash
cd backend
pip install -r requirements-dev.txt
pytest -v
```

15 tests as of this writing, covering: JWT/password security primitives,
the semantic chunker's four core behaviors (heading boundaries, table
atomicity, sentence-safe splitting, overlap), the RAG engine's
never-hallucinate path and citation generation, and admin RBAC
enforcement. `ruff check app tests` for linting.

Frontend: `cd frontend && npm run lint && npm run build` (there is no
frontend unit test suite yet — component tests would be a good next
addition).

## Adding a new LLM provider

1. Implement `app/services/llm/base.py`'s `LLMProvider` interface
   (`complete`, `stream`, `embed`, `health_check`) in a new file — see
   `app/services/llm/future_providers.py` for the scaffolds already
   sitting there for vLLM/Ollama/NIM/llama.cpp/HuggingFace.
2. Register it in `PROVIDER_REGISTRY` in `app/services/llm/factory.py`.
3. Set `LLM_PROVIDER=your_new_provider` in the environment.

Nothing else in the codebase (the RAG engine, chat routes, or embedding
pipeline) needs to change, since they all depend only on the
`LLMProvider` interface.

## Adding a new document format extractor

1. Implement `app/services/extraction/base.py`'s `TextExtractor`
   interface in a new file under `app/services/extraction/`.
2. Register it in `_REGISTRY` in `app/services/extraction/registry.py`.
3. Add the extension to `ALLOWED_FILE_EXTENSIONS` in `app/core/config.py`
   and the extension-to-`FileType` map in
   `app/services/upload/validation.py` and `app/services/document_service.py`.

See `docs/architecture.md`'s coverage note for what's already implemented
vs. deferred (`.doc`, `.xls`, `.zip`).

## Database migrations

```bash
cd backend
alembic revision --autogenerate -m "add foo column"
alembic upgrade head
```

Always review an autogenerated migration by hand before committing it —
Alembic's diffing is good but not perfect, especially around pgvector
index options and enum type changes.

## Code organization principles this codebase follows

- **Provider/registry pattern** for anything that might need swapping
  later (LLM backend, text extractors) — see above.
- **Services own business logic and DB queries; API routers only handle
  HTTP concerns** (parsing the request, calling a service, mapping
  exceptions to status codes). A `select()` inside an `app/api/*.py` file
  probably belongs in a service instead.
- **Every DB query that touches user data filters by owner_id** (or, for
  admin routes, is explicitly gated by `require_admin`). This is the
  tenant-isolation guarantee — don't add a query that skips it.
- **Schemas (`app/schemas/`) are the wire format; models (`app/models/`)
  are the storage format.** Don't return an ORM model directly from a
  route; always go through a Pydantic response_model.

Never print `.env`, run verbose Compose configuration, or paste keys into chat. Use `docker compose config --quiet`.

## When Docker Linux engine works

```powershell
powershell -NoProfile -File .\scripts\start-local.ps1 -Test
```

This performs a no-cache build, starts services with health-gated dependencies, migrates the database, compares the imported API/worker modules against checkout SHA-256 hashes, checks dependencies and model access, then executes the real RAG acceptance script. No host Python, PostgreSQL, Redis, AWS CLI or Node installation is needed. The only external model credential is Gemini.

Subsequent starts without source changes can use `-SkipBuild`. To repeat only the real API acceptance:

```powershell
docker compose exec -T backend python /opt/knowledgegpt-scripts/smoke_test.py --base-url http://localhost:8000 --s3-transport-url http://minio:9000 --verify-database
```

The runner creates two disposable users, one PDF and two knowledge bases per run. It preserves test rows for inspection and prints only resource IDs. Repeated runs consume a small amount of real Gemini usage and remain subject to rate limits; on HTTP 429 wait for the applicable rate window, do not disable protection. Existing data volumes are never automatically erased.

API and worker share one Compose environment anchor, provider settings and source image. The provider factory remains intact. Gemini reads `settings.GOOGLE_GEMINI_API_KEY`, explicitly requests 1536 embedding dimensions, checks shape and finite nonzero values, and normalizes vectors. ORM and initial migration use `vector(1536)` and a cosine HNSW index. Migration `0002_embedding_contract` validates the legacy schema; it only resizes an empty incompatible table. Populated incompatible dimensions fail safely, requiring backup and deliberate re-embedding. Startup also rejects existing vectors from a different model. Do not truncate vectors, drop data, or change the similarity threshold to force acceptance.

## Local services and limits

- PostgreSQL 16 with pgvector; Redis for Celery and rate limits.
- MinIO for the application's required temporary S3 uploads. Published only on loopback. Originals are deleted after durable chunk persistence; extracted text/vectors remain in PostgreSQL.
- ClamAV remains enabled, including for local ingestion. Its first signature download can delay health readiness; inspect `docker compose logs --tail=80 clamav` if necessary.
- One API worker and one Celery processing worker for the Dell. Celery beat is retained because the existing application uses it to reconcile stalled documents every five minutes.
- Frontend at `http://localhost:3000`, API at `http://localhost:8000`. Ports for storage, database and Redis also bind only to `127.0.0.1`. Do not expose this development stack publicly.

API `/health` is liveness only. `/health/deep` remains admin-only; the operator CLI checks database/migration/model contract, Redis, bucket, ClamAV and real Gemini model metadata without creating a public diagnostics endpoint. Metadata access is not proof of a successful embedding or answer.

## Real acceptance assertions

The two-page PDF fixture contains a fictional code word `PINEAPPLE-TELESCOPE-7` on page 1 and a fictional archive retention period of `37 days` on page 2. Questions and expected facts are fixed. Model output can vary, but acceptance conditions do not.

1. Register/login user A; create KB and session through actual HTTP endpoints.
2. Generate a real PDF, obtain presigned URL, PUT bytes to MinIO, verify stored byte length, then confirm upload.
3. Poll actual Celery-driven processing to completed, fail on error or deadline. Require two extracted pages and at least two chunks.
4. Ask the page-1 question and a page-2 second turn. Require streamed text, successful terminal event and expected facts; validate document name/ID, chunk ID, page and relevant citation excerpt.
5. Ask an unrelated Neptune question. Require structural `no_answer`, no citations and no recorded completion model. Never lower the production threshold just to pass.
6. Register/login user B; deny foreign KB/document/chat access and foreign document confirmation/session creation. Ask user A's question with A's document filter from B's empty KB; require no-answer.
7. Re-read messages through fresh HTTP requests; citations must match the streamed terminal events. Check actual PostgreSQL vectors are 1536-dimensional, normalized and model/owner/KB scoped; match citation excerpts to stored chunks. Use real question embeddings to independently test owner-filtered SQL retrieval. Require zero RAG completion usage for B.

The in-container HTTP test connects to `minio:9000` while preserving the original signed `Host` header. This tests real S3 signatures and bytes; it does **not** validate browser CORS. Do the following browser check before declaring the full golden path verified.

## Fresh migration verification without losing existing data

On a new Dell checkout with no KnowledgeGPT volumes, the first startup exercises a clean empty database. If volumes already exist, preserve them. Stop the usual stack with `docker compose down` (no `-v`), set `$env:COMPOSE_PROJECT_NAME = 'knowledgegpt-golden-fresh'` to a previously unused project name, then run the startup script. This creates separate empty named volumes on the same ports. After testing, stop that project without deleting its volumes and remove the override with `Remove-Item Env:COMPOSE_PROJECT_NAME` before resuming the original stack. Do not run two projects on the same host ports at once.
